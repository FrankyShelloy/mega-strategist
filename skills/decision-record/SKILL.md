# Skill: decision-record
## Когда применять
Решение принято — на G2, G3 или в рабочем порядке. Запись делается сразу: через неделю причина выбора забывается, остаётся только результат.
## Цель
Связать решение с владельцем, метрикой, порогом и датой или триггером пересмотра, чтобы его можно было проверить и при необходимости заменить, не переписывая историю.
## Вход
- `strategy/*.md`, `options/`, `claims.md`.
- Подтверждение человека на шлюзе или явная договорённость.
- Дата, владелец и метрика, по которой решение будет проверяться.
## Правила
- Одна строка — одно решение. «Сделать стратегию» — не решение.
- Решение формулируется глаголом: что именно делаем и что не делаем.
- У каждой строки есть владелец, метрика с порогом и условие пересмотра.
- Дата пересмотра — конкретная (`YYYY-MM-DD`) или триггер («падение метрики ниже X две недели»).
- Старые строки не удаляются и не переписываются; новое решение ссылается на заменяемое.
- Альтернативы фиксируются коротко: что рассматривали и почему отказались.
## Шаги
1. Прочитай подтверждённое решение и связанные артефакты.
2. Сформулируй решение одним предложением с границами.
3. Запиши альтернативы и причину отказа от них.
4. Назначь владельца и метрику с порогом.
5. Определи условие и дату пересмотра.
6. Добавь строку в `decision-log.md`; не меняй прошлые строки.
7. Обнови `state.md`: стадия, следующий шаг, шлюз.
8. Запиши действие в `run-log.csv`.
## Выход
`projects/<slug>/decision-log.md`:
| # | Решение | Дата | Владелец | Метрика и порог | Условие пересмотра | Пересмотр | Статус |
|---|---|---|---|---|---|---|---|
| D1 |  |  |  |  |  |  | proposed |
## Критерий готовности
- Решение конкретное и проверяемое, с границами.
- Есть владелец и метрика с порогом.
- Есть дата или триггер пересмотра.
- Альтернативы и причина выбора видны.
- Статус отражает реальность: `proposed`, `accepted`, `rejected`, `superseded`.
- Прошлые решения не удалены.
## Когда остановиться и позвать человека
- Нет владельца решения.
- Нет метрики, по которой решение можно проверить.
- Решение меняет цену, бюджет, юридические обязательства или репутацию.
- Человек просит записать решение без обсуждения альтернатив — зафиксируй это в `corrections.md`.
## Частые ошибки
- Записывать тему вместо решения.
- «Владелец: команда» без имени роли.
- Метрика без порога.
- Пересмотр «когда-нибудь».
- Тихо переписать старую строку под новый результат.
